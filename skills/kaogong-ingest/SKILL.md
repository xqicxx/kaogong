# 讲义拍照 → markdown → 落库（kaogong-ingest）

把用户拍的讲义书页变成 Obsidian 里可查、可复习的笔记。**机器负责把字从图里搬出来，你负责对着原图校准。**

## 四步，一步都不能省

### ① 跑流水线（机器产出 → `_raw/`）

```bash
~/.pi/bin/kaogong-ocr.sh --source "逻辑论证-归因论证" --module 行测/判断推理 图1.jpg 图2.jpg
```

- `--module` 取 `行测/{常识判断,言语理解与表达,数量关系,判断推理,资料分析}` 或 `申论/{归纳概括,综合分析,提出对策,贯彻执行,申发论述}`；不确定就省略（落 `_inbox`）
- 机器产出落到 `考公/_raw/<模块>/`，front-matter 里 `proofread: false`
- 速度约 0.7s/张

### ② 校准（这步是你的活，不能跳过）

1. **打开原图看**（read 图片文件），把 `_raw/` 里的机器产出**逐句对照**
2. 拿不准就裁切放大再看：

```bash
~/.pi/bin/crop 原图.jpg /tmp/zoom.png <x> <y> <宽> <高> 2.5
```

坐标从图左上角算，倍数 2–2.5 足够看清密排小字。

1. 校准后的版本写到 `考公/<模块>/<讲义>-pNNN.md`，front-matter 改 `proofread: true` + `proofread_by: pi`
2. **文件尾部留一段校准记录**，逐条写明改了什么：

```markdown
<!-- 校准记录（原样见 _raw/）
  陈迷 → 陈述          太颈鹿 → 长颈鹿
  「①别有他因，引入區干术现…」→ ①另有他因：引入题干未提及的其他影响因素…
-->
```

### ③ 写完笔记更新检索索引

```bash
qmd update          # 1 秒，增量；不跑的话新笔记搜不到
```

找同知识点题、关联错题靠 `qmd search <词> -c notes` —— **必须带 `-c notes`**，
不带会去搜 pi-memory，永远搜不到笔记。

### ④ `_raw/` 永不删

原始识别件必须留着 —— 任何时候都要能对回机器原文，分得清是**识别错**还是**校错**。

### ⑤ 切考点（可选，用户要卡片时做）

```bash
python3 ~/code/kaogong/pipeline/split.py --module 行测/判断推理 --lecture <讲义名> \
  "$HOME/Documents/Obsidian Vault/考公/行测/判断推理/<讲义>-p001.md" ...
```

- 骨架 → `考公/<科目>/<模块>/<讲义>.md`；卡片 → `考公/考点/<考点名>.md`
- 机械切法（行首 ①②③ + 第一个冒号分术语/解释）**约七成可直接用**
- 剩下的卡面要你重写：像「支持原观点或质疑反对者 是什么？」这种冗长问句，应该改成能真正触发回忆的问法
- 新卡片要初始化排期：`python3 ~/code/kaogong/pipeline/review.py init`

## 错误源排序（决定你会看到什么错）

```text
① 纸张背面透印 —— 头号元凶。书页薄，背面文字镜像叠上来
   → 让用户拍的时候背后垫黑纸/黑卡，最有效
② 红笔标注 —— 已由去红笔步骤处理（R−max(G,B)>38 抹白）
③ 页边阴影 / 页脚暗角 —— 让用户两侧打光、别用顶光
④ 字形混淆 —— 入/人、殊/珠、千/干，只能靠校准
```

## 硬规则

- ❌ 不要把机器产出直接当成品交给用户
- ❌ 不要删 `_raw/`
- ❌ 不要拿「错误关键词消失」当质量指标 —— 会同时把「乱码」和「空白」判成正确
- ✅ 质量评估用**真词命中 + 字数**双指标，并且**真读一遍输出**
- ✅ 每次只跑一个模块，跑完报数字（张数、耗时、校准了几处）

## 做完汇报格式

```text
N 张 → 考公/<模块>/<讲义>-pNNN.md（校准 N 处，原始件在 _raw/）
耗时 X ms/张
剩余存疑：<列出来，或“无”>
```
